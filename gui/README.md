# GUI: PDF Translator

Графический интерфейс (CustomTkinter) для пайплайна перевода PDF-книг
английский → русский. Три этапа: **Извлечение → Перевод → Сборка PDF**,
каждый запускается по отдельности или целиком одной кнопкой.

GUI живёт на ветке `gui` (на `main` его нет).

## Запуск

```bash
# из корня репозитория, в активном виртуальном окружении
python -m gui
```

Окно 950×750, тёмная тема. Структура:

```
┌ PDF Translator            Готово            [⚙ Настройки]┐
│ [1. Извлечение] [2. Перевод] [3. Сборка PDF]  ← вкладки  │
│ [Входной PDF / папка / Page Range]  [▶ Запустить]        │
├──────────────────────────────────────────────────────────┤
│ [☑ Выполнить все шаги]  [▶ Пуск]  [⏹ Стоп]               │
├──────────────────────────────────────────────────────────┤
│ Лог (stdout/stderr шагов, tqdm-прогресс)                 │
└──────────────────────────────────────────────────────────┘
```

Статус в шапке: «Готово» / «⏳ Работает...». Окно не блокируется во время
работы — шаги исполняются в фоновом потоке, лог пишется на лету.

## Вкладка 1. Извлечение

| Поле / кнопка | Назначение |
|---|---|
| **Выбрать PDF** | Входной PDF. После выбора выходная папка подставляется автоматически: `rendered/<имя_книги>` |
| **Выбрать папку** | Выходная папка (разблокируется после выбора PDF). Marker создаёт внутри подпапку с именем книги |
| **Page Range** | Необязательно. Формат: `1-10`, `20`, `30-40`, `1-10, 20, 30-40` (проверяется валидация) |
| **▶ Запустить** | Запускает `marker_single` (OCR-извлечение) |

Результат: `rendered/<книга>/<книга>.md` + извлечённые картинки
(`_page_N_*.jpeg`) + `<книга>_meta.json`.

Использование LLM в маркере (`--use_llm` + endpoint) берётся из
`config/translation_config.yaml` — галочка **Use LLM** на вкладке
«Настройки → Извлечение».

## Вкладка 2. Перевод

| Поле / кнопка | Назначение |
|---|---|
| **Выбрать .md** | Исходный markdown из этапа 1. После выбора путь к `<имя>_ru.md` подставляется на вкладке 3 автоматически |
| **▶ Запустить** | Запускает `scripts/translate_marker.py --file <md>` |

Переводится **только выбранный файл** (не вся папка), блоки шлются на
серверы из `server_pool` параллельно. Результат: `<имя>_ru.md` рядом с
исходником.

## Вкладка 3. Сборка PDF

| Поле / кнопка | Назначение |
|---|---|
| **Выбрать _ru.md** | Переведённый markdown из этапа 2 |
| **▶ Собрать PDF** | Запускает `pandoc` (xelatex) |

Результат: `<имя>_ru.pdf` в той же папке. Верстка (шрифты, размер) — из
`config/pandoc_metadata.yaml`, редактируется в «Настройки → Сборка PDF».

## Полный пайплайн одной кнопкой

1. На вкладке 1 выбрать входной PDF (выходная папка подставится сама).
2. Поставить галочку **«Выполнить все шаги»** — кнопка **▶ Пуск**
   разблокируется (без галочки Пуск неактивен).
3. Жать **▶ Пуск** — этапы идут цепочкой 1 → 2 → 3, каждый стартует по
   завершении предыдущего.

**⏹ Стоп** прерывает текущий этап и дальнейшую цепочку.

## Настройки (⚙ )

Диалог с тремя вкладками, пишет в YAML-конфиги (round-trip через
`ruamel.yaml` — комментарии, `|`-блоки и порядок ключей сохраняются):

| Вкладка | Поле | Ключ в конфиге |
|---|---|---|
| Извлечение | Output Dir | `target_folder` в `config/translation_config.yaml` |
| Извлечение | Use LLM (галочка) | `use_llm` в `config/translation_config.yaml` |
| Перевод | Server Pool (по одному URL на строку) | `server_pool` в `config/translation_config.yaml` |
| Перевод | API Key | `api_key` в `config/translation_config.yaml` |
| Перевод | Model Name | `model_name` в `config/translation_config.yaml` |
| Сборка PDF | Font Size / Main Font / Mono Font | `fontsize` / `mainfont` / `monofont` в `config/pandoc_metadata.yaml` |

**Сохранить и закрыть** — применить и сохранить, **Отмена** — закрыть без
сохранения.

## Требования

- LLM-сервер(ы) из `server_pool` должны быть доступны (этап 2) — настройка
  серверов перевода описана в [корневом README](../README.md#3-настройки-подключения-к-модели-перевода).
- `marker_single` в PATH (этап 1), OCR-модели — в `models/`.
- `pandoc` + `xelatex` + шрифты из конфига (этап 3).
